## 🔧 Инструкции для следующих сессий

### ⚠️ Важно: Работа с Git

**НЕ коммитить в `main`!** Все изменения вносить в отдельные ветки:

```bash
# Создать новую ветку для задачи
git checkout -b <branch-name>

# Примеры именования веток:
# - feature/<название-фичи>
# - fix/<что-исправляем>
# - design/<название-задачи>

# После завершения работы:
git add .
git commit -m "type: описание изменений"
git push -u origin <branch-name>

# Создать Pull Request через GitHub UI или:
gh pr create --title "Description" --body "Changes"
```

### 📋 Типы коммитов (Conventional Commits)

- `feat:` — новая фича
- `fix:` — исправление бага
- `design:` — изменения дизайна/стилей
- `refactor:` — рефакторинг без изменений функциональности
- `docs:` — обновления документации
- `chore:` — вспомогательные изменения (конфиги, зависимости)

### 🎨 Дизайн-принципы

При внесении изменений в дизайн:
1. Проверять консистентность с существующими секциями
2. Использовать Tailwind spacing scale (p-4, p-6, p-8...)
3. Сохранять цветовую палитру (проверять в globals.css)
4. Тестировать на mobile/tablet/desktop
