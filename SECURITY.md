# 🔒 Политика безопасности

## 📌 Важно: Приватный проект

Этот проект является **приватным** и не подразумевает открытое сообщество контрибьюторов.

**Вопросы безопасности должны сообщаться только авторизованным участникам проекта.**

## Сообщение о уязвимостях

Если вы обнаружили уязвимость в проекте, **пожалуйста, не создавайте public issue** на GitHub.

Вместо этого сообщите о проблеме напрямую:

- **Email:** perpendikulyar@gmail.com
- **Telegram:** @mnikolashin

### Что указывать в отчёте:

1. **Тип уязвимости** (например, XSS, CSRF, инъекция, утечка данных)
2. **Критичность** (Critical/High/Medium/Low)
3. **Шаги для воспроизведения**
4. **Возможный ущерб**
5. **Ваша информация** (опционально — для благодарности)

### Сроки реагирования:

- **Critical/High:** 24 часа — подтверждение получения, 7 дней — план устранения
- **Medium/Low:** 72 часа — подтверждение, 14 дней — план устранения

## Рекомендации для контрибьюторов

### Безопасность кода:

- ✅ Никогда не коммитить API-ключи, токены или пароли
- ✅ Использовать `.env` файлы для sensitive данных (они в `.gitignore`)
- ✅ Проверять зависимости на уязвимости (`npm audit`)
- ✅ Использовать HTTPS для всех внешних ссылок
- ✅ Валидировать все входные данные

### Безопасность репозитория:

- ✅ Не публиковать информацию о внутренних процессах
- ✅ Не делиться ссылками на приватные ресурсы в open-source проектах
- ✅ Регулярно обновлять зависимости
- ✅ Использовать двухфакторную аутентификацию для GitHub

## Закрытый характер проекта

**Важно:** Все изменения в код вносятся только по выданному доступу к исходным кодам.
