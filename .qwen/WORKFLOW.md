**Проект:** Michael Nikolashin Portfolio  
**Версия:** 1.0 (Март 2026)

## 📚 О системе

Этот проект использует **субагентов** для разделения контекста между дизайном и разработкой.

### Архитектура

```
┌─────────────────────────────────────────────────────────┐
│                   Ты (User)                             │
│            "Сделай компонент по макету"                 │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│              Основной агент (Qwen Code)                 │
│     Анализирует задачу, выбирает инструмент             │
└──────────────┬──────────────────────┬──────────────────┘
               │                      │
               ▼                      ▼
    ┌──────────────────┐   ┌──────────────────┐
    │  Designer Agent  │   │ Developer Agent  │
    │  (Figma, UI/UX)  │   │  (React, Code)   │
    └────────┬─────────┘   └────────┬─────────┘
             │                      │
             ▼                      ▼
    ┌──────────────────┐   ┌──────────────────┐
    │   Figma MCP      │   │   Codebase       │
    │   design-tokens  │   │   components     │
    └──────────────────┘   └──────────────────┘
```

## 🎯 Когда использовать агентов

### Вызывать **Designer Agent** через `task`:

| Задача | Пример |
|--------|--------|
| Создание нового UI | "Спроектируй карточку кейса" |
| Экспорт из Figma | "Экспортируй цвета из макета" |
| Дизайн-ревью | "Проверь контрастность цветов" |
| UI Kit | "Создай UI Kit для портфолио" |

### Вызывать **Developer Agent** через `task`:

| Задача | Пример |
|--------|--------|
| Код по макету | "Создай компонент по Figma" |
| Интеграция | "Интегрируй дизайн-токены" |
| Код-ревью | "Проверь код на best practices" |
| Оптимизация | "Ускорь загрузку страницы" |

### Работать с **Основным агентом** (я):

| Задача | Пример |
|--------|--------|
| Общие вопросы | "Какая структура проекта?" |
| Навигация | "Где лежит portfolio.json?" |
| Координация | "Запусти дизайнера, потом разработчика" |
| Контекст | "Что сделано в Фазе 1?" |

## 🚀 Примеры Workflow

### Workflow 1: Создание компонента с нуля

```
1. Ты: "Нужна карточка кейса по макету"
   ↓
2. Основной агент: 
   - Запускает Designer Agent
   - Задача: "Спроектируй CaseCard, экспортируй токены"
   ↓
3. Designer Agent:
   - Создаёт макет в Figma (или берёт существующий)
   - Экспортирует design-tokens.json
   - Возвращает спецификацию
   ↓
4. Основной агент:
   - Запускает Developer Agent
   - Задача: "Создай CaseCard.js по токенам"
   ↓
5. Developer Agent:
   - Читает design-tokens.json
   - Генерирует React компонент
   - Сохраняет в components/CaseCard/
   ↓
6. Основной агент:
   - Показывает результат
   - Предлагает закоммитить
```

**Команда:**
```
task: "Создай карточку кейса — от дизайна до кода"
  subagent_type: general-purpose
  prompt: |
    1. Спроектируй CaseCard в Figma (или используй существующий макет)
    2. Экспортируй дизайн-токены
    3. Создай React компонент по токенам
    4. Сохрани в components/CaseCard/
```

---

### Workflow 2: Дизайн-ревью

```
1. Ты: "Проверь дизайн на accessibility"
   ↓
2. Основной агент:
   - Запускает Designer Agent
   - Задача: "WCAG AA проверка"
   ↓
3. Designer Agent:
   - Проверяет контраст цветов
   - Проверяет размеры touch targets
   - Возвращает отчёт
```

**Команда:**
```
task: "Проверь accessibility"
  subagent_type: general-purpose
  prompt: |
    Проверь дизайн на соответствие WCAG AA:
    1. Контрастность цветов (min 4.5:1 для текста)
    2. Touch targets (min 44px)
    3. Focus состояния
    Верни отчёт с рекомендациями.
```

---

### Workflow 3: Синхронизация Figma ↔ Код

```
1. Ты: "Обнови компоненты по новому макету"
   ↓
2. Основной агент:
   - Запускает Designer Agent
   - Задача: "Экспортируй обновлённые токены"
   ↓
3. Designer Agent:
   - Получает актуальный макет из Figma
   - Обновляет design-tokens.json
   ↓
4. Основной агент:
   - Запускает Developer Agent
   - Задача: "Обнови компоненты по новым токенам"
   ↓
5. Developer Agent:
   - Сравнивает старые/новые токены
   - Обновляет компоненты
   - Возвращает diff
```

## 🎨 Ручное переключение режимов

### Через `skill` tool:

```
skill: "figma"  # Включает Figma контекст
```

### Через `task` tool:

```
task:
  description: "Дизайн задача"
  subagent_type: "general-purpose"
  prompt: |
    Ты Designer Agent. Твоя задача: ...
    (см. .qwen/agents/designer.md)
```

### Через систему сообщений:

```
@designer Спроектируй кнопку

```

## ⚠️ Best Practices

### 1. Минимизируй контекст
- Не загружай весь Figma файл — только нужные frames
- Используй `file_filtering_options` для игнорирования лишнего

### 2. Чёткие boundaries
- Designer: Figma → токены → JSON
- Developer: JSON → код → commit
- Основной: координация, контекст проекта

### 3. Сохраняй артефакты
- Designer создаёт `figma/design-tokens.json`
- Developer читает токены, создаёт компоненты
- Коммить токены в git (история изменений)

### 4. Итеративность
- Сначала прототип в Figma
- Потом экспорт токенов
- Потом генерация кода
- Потом ревизия

## 🔧 Настройка для новой сессии

### 1. Проверить MCP конфиг

```bash
cat ~/.config/mcp/servers.json
# Убедиться что FIGMA_API_TOKEN настроен
```

### 2. Проверить скиллы

```
.qwen/skills/figma/SKILL.md — существует
.qwen/agents/designer.md — существует
.qwen/agents/developer.md — существует
```

### 3. Тестовый запуск

```
task: "Тест"
  subagent_type: general-purpose
  prompt: "Прочитай design-tokens.json и верни цвета"
```

## 🆘 Troubleshooting

### "Агент не понимает задачу"
- Уточнить промпт, добавить контекст
- Использовать `.qwen/agents/*.md` как reference

### "Figma MCP не подключается"
- Проверить токен в `~/.config/mcp/servers.json`
- Проверить fileKey в URL Figma

### "Контекст загрязняется"
- Использовать отдельные `task` вызовы
- Очищать контекст между задачами
